# 1. Introduction

## 1.1 Purpose

This Software Requirements Specification (SRS) document describes the functional and non-functional requirements for the **Old Bicycles Marketplace** system - an online platform for buying and selling used bicycles. This document is intended for:

- Development Team (Frontend, Backend, Mobile)
- QA/Testing Team
- Product Owner and Stakeholders
- System Architects
- Operations and Support Team

## 1.2 Scope

### 1.2.1 Product Name

**Old Bicycles Marketplace**

### 1.2.2 Product Description

An e-commerce platform specializing in buying and selling used bicycles, connecting Sellers, Buyers, Inspectors, and Administrators. The system supports listing, searching, chatting, deposits, bike inspections, and transaction management.

### 1.2.3 Objectives

- Create a safe and transparent platform for trading used bicycles.
- Increase trust through an inspection and rating system.
- Simplify the transaction process with integrated chat and deposit features.
- Provide effective management tools for admins.

### 1.2.4 Benefits

- **Seller**: Reach more customers, easily manage listings.
- **Buyer**: Find suitable bikes, peace of mind with inspected bikes.
- **Platform**: Collect service fees, build a bicycle community.

## 2.4 Constraints

### 2.4.1 Regulatory Requirements

- Comply with Vietnam E-commerce Law
- Personal Data Protection Decree (PDPD) compliance
- Payment policies per State Bank regulations

### 2.4.2 Technical Constraints

- Web-first approach (no mobile app in phase 1)
- Response time < 3 seconds for all operations
- Support image upload max 10MB/file, video 100MB/file
- Max 20 images and 2 videos per listing

### 2.4.3 Business Constraints

- **Timeline**: Phase 1 completion in 4 months
- **Budget**: Within approved budget
- **Team**: 3 Frontend, 2 Backend, 1 DevOps, 1 QA

#### FR-AUTH-001: User Registration

| **Attribute** | **Value** |
| --- | --- |
| **ID** | FR-AUTH-001 |
| **Description** | The system shall allow users to register a new account with email or phone number, selecting Buyer or Seller role |
| **Priority** | Must |

**Inputs:**

- Email or phone number
- Password (min 8 chars, uppercase, number)
- Full name

3. Hash password with bcrypt
4. Send OTP verification

### 3.3.2 Bike Listing Management (Seller)

#### FR-SELL-001: Create Bike Listing

| **Attribute** | **Value** |
| --- | --- |
| **ID** | FR-SELL-001 |
| **Description** | Sellers shall be able to post bike listings with full technical details |
| **Priority** | Must |

**Inputs (Required per BR01):**

- Title
- Bike Type (Road, Mountain, City, Touring, BMX)
- Brand
- **Frame Size** (S/M/L or cm) ⭐
- **Wheel Size** (26, 27.5, 29, 700c) ⭐
- **Brake Type** (Disc/V-brake) ⭐
- **Frame Material** (Aluminum/Carbon/Steel) ⭐
- Drivetrain/Groupset (e.g., Shimano 105)
- Condition (New 90%, Used, Needs Repair)
- Price, Original Price (optional)
- Detailed Description
- Selling Address (Province/City, District)

**Required Images (per BR02):**

- Full bike image ⭐
- Groupset image ⭐
- Serial number image ⭐
- Additional images (max 17)
- Video (0-2, max 100MB)

**Processing:**

1. Validate all required fields
2. Validate image types
3. Upload and compress media
4. Create listing with status "Pending"
5. Notify admin for approval
6. Set expires_at = created_at + 30 days

| **Priority** | Must |

**Reports:**

- Users: New registrations, active users, churn
- Listings: New, sold, pending, removed
- Revenue: Transaction fees, deposits, inspection fees
- Performance: Response times, error rates

# 4. Business Rules

## 4.1 Listing Rules

| **BR ID** | **Rule** | **Description** |
| --- | --- | --- |
| **BR01** | Technical Data Standards | When posting, Seller MUST enter: Frame Size, Wheel Size, Brake Type, Frame Material |
| **BR02** | Real Images | Minimum 3 images: Full bike, Groupset, Serial number |
| **BR03** | Listing Duration | Listing valid for 30 days, then must be renewed |
| **BR04** | New Listing Status | New Listing = "Pending", requires Admin approval to display |

## 4.2 Inspection Rules

| **BR ID** | **Rule** | **Description** |
| --- | --- | --- |
| **BR05** | Badging Process | "Verified" Badge ONLY issued by Inspector, Seller cannot self-apply |
| **BR06** | Inspection Validity | Report valid for 7 days or until sold. Component change = badge void |
| **BR07** | Report Transparency | Inspection report MUST be public on product detail page |

## 4.3 Transaction Rules

| **BR ID** | **Rule** | **Description** |
| --- | --- | --- |
| **BR08** | Escrow Mechanism | Deposit held by intermediary. Correct Delivery = transfer to Seller. Cancellation/Wrong Description = refund Buyer |
| **BR09** | Service Fee | Collect x% fee on successful transaction or inspection fee |

## 4.4 Trust & Safety Rules

| **BR ID** | **Rule** | **Description** |
| --- | --- | --- |
| **BR10** | Rating Condition | Buyer can ONLY rate after order is "Completed" |
| **BR11** | Dispute Resolution | Inspector's result is priority basis for Admin refund decision |

# Appendix A: Glossary

| --- | --- |

| **Verified Badge** | Label indicating bike has been inspected |
| **Wishlist** | Buyer's list of favorite bikes |
